# QA Copilot · 测试工程师 AI 工作台 需求文档（PRD）

版本：v0.1（草案，待评审）
日期：2026-11-10
状态：需求阶段，未开始开发

---

## 1. 背景与目标

测试工程师的日常大量消耗在重复性文字工作上：把需求翻译成用例、把手工步骤转成自动化脚本、在 CI 日志里找失败原因、修被 UI 改动弄坏的定位器、造测试数据。现有 AI 工具（Testim、mabl、testRigor、KaneAI、Postman Agent 等）证明了这些场景的价值，但多为 SaaS 平台，价格高、绑定自家执行环境、难以离线/私有使用。

本项目目标：做一个**测试工程师主导、模型辅助生成、本地优先**的 AI 工作台。不是"全自动测试平台"，而是把测试工程师从文字搬运工解放出来：AI 产出初稿，工程师审核、修改、确认。

**核心原则**：AI 生成的一切都是草稿，最终质量由工程师把关。工具不伪装成"已执行验证"，不做无法兑现的承诺。

## 2. 目标用户

| 用户 | 核心诉求 |
|---|---|
| 手工测试工程师 | 需求→用例快、覆盖全、能导出给团队 |
| 自动化测试工程师 | 脚本能跑、定位器稳、结构规范、能融入现有框架 |
| 测试开发（SDET） | 失败诊断快、根因准确、修复建议可落地 |
| 测试负责人 | 覆盖缺口可见、风险排序清晰、产出可汇报 |

## 3. 市场调研摘要

| 竞品 | 核心能力 | 本项目借鉴点 |
|---|---|---|
| Testim | SmartLocate 自愈定位器；按错误类型聚合失败的 RCA | 定位器修复建议；失败分类统计 |
| mabl | AI-native agentic testing：创建→执行→失败分析→恢复全链路 | 诊断→修复建议的完整闭环 |
| testRigor | 自然语言（纯英文）生成测试；自愈；测试 AI 原生功能 | 中文自然语言生成用例与脚本 |
| LambdaTest KaneAI | PRD/Jira/PDF/截图→结构化场景；导出 Selenium/Playwright/Appium；测试可观测性 | 多格式输入→结构化输出；多框架导出 |
| Postman Agent | API 测试脚本生成、覆盖建议、文档、调试 | API 测试场景的 AI 辅助 |
| 通用自愈模式 | 分析→定位根因→可修复则自动修 | 定位器修复建议的输出格式 |

**差异化定位**：竞品绑定自家执行环境与 SaaS 订阅；本项目是**模型无关、本地优先、工程师可控**的生成工作台——不执行测试，只负责"让测试资产从 0 到 1 变得极快"。

## 4. 功能需求

### F1 需求 → 测试用例（P0 · MVP）

**输入**：需求文档/用户故事/验收标准（粘贴文本，支持 Markdown）。
**输出**：
- 测试分析（功能点拆解、边界值、异常流、隐含需求）
- 结构化用例列表：编号、标题、前置条件、步骤、预期结果、优先级（P0-P3）、类型（功能/边界/异常/安全/性能/兼容/无障碍）
- Gherkin 格式（可选切换）
- 需求追溯矩阵（需求点 ↔ 用例编号）
- 导出：Markdown / CSV / JSON

**约束**：
- 用例必须包含：正常流、边界值、无效输入、权限/越权、并发/重复提交（如适用）
- 每条用例的预期结果必须可验证（不含"正常显示"这类模糊描述）
- 覆盖不足时主动列出遗漏场景建议

### F2 自动化脚本生成（P0 · MVP）

**输入**：用例（手写或 F1 产出）、目标框架、现有代码上下文（可选粘贴）。
**输出**：
- 可运行的测试脚本（Playwright TypeScript 为默认）
- Page Object Model 结构（如选择 POM 模式）
- 定位器策略：优先 data-testid > aria > 语义 CSS，避免绝对 XPath
- setup/teardown、测试数据准备、断言
- 框架/语言选项：Playwright TS（默认）、Cypress JS、Selenium Java、Selenium Python、Appium（P1）

**约束**：
- 禁止固定 sleep；使用显式等待
- 生成的脚本未经实际运行，输出标注"未执行验证"
- 提供现有代码时可增量修改而非重写

### F3 失败诊断与修复建议（P0 · MVP）

**输入**：失败的测试名、错误信息/堆栈、CI 日志片段（可选：截图描述、最近变更说明）。
**输出**：
- 失败分类：产品 Bug / 测试脚本 Bug / 环境问题 / 测试数据问题 / 不稳定（Flaky）
- 根因分析：按置信度排序的候选原因，每条附日志中的证据行
- 修复建议：最小改动方案（优先），避免大重写
- 下一步排查步骤
- 如可自动修：给出修改后的代码片段

**约束**：
- 不确定时明确说"需要更多信息"，并列出还需要什么
- 不假设是产品 Bug——先排查测试自身

### F4 Locator 修复（P1）

**输入**：失效定位器、当前 DOM 片段、报错信息。
**输出**：
- 3 个候选新定位器，按稳定性排序（data-testid > aria-label > 语义 CSS > 文本 > 避免完整 XPath）
- 每个候选的稳定性评分与理由
- 如果 DOM 中不存在目标元素：明确说明元素已消失，而非硬给定位器

### F5 API 测试生成（P1）

**输入**：curl 命令 / OpenAPI 规范片段 / 接口文档文字。
**输出**：
- 正向 + 负向 + 边界 + 认证缺失 + 参数篡改用例
- 断言：状态码、响应体字段、schema 结构、响应时间阈值
- 环境变量化（base URL、token、动态 ID）
- 导出为 Postman Collection JSON 或脚本

### F6 测试数据工厂（P1）

**输入**：字段列表（名称、类型、规则、约束）。
**输出**：
- 正常值、边界值、无效值、极端值
- JSON / CSV / SQL INSERT 格式
- 敏感数据脱敏提示

### F7 用例评审与覆盖缺口分析（P1）

**输入**：需求 + 现有用例列表。
**输出**：
- 覆盖矩阵：需求点 × 用例覆盖情况
- 缺失场景清单（按风险排序）
- 冗余/重复用例建议
- 遗漏的异常流与隐含需求

### F8 模板与团队规范（P1）

- 团队自定义用例模板、命名规范、自动化风格指南
- 作为系统提示词注入，保证产出符合团队规范
- 模板可导入导出

### F9 工作台基础（P0 · MVP）

- 项目 / 测试套件组织，标签筛选
- 会话与产出历史，搜索
- 全部数据导出/导入（JSON）
- 收藏与置顶
- 深色模式

### P2（暂不实现，规划中）

- GitHub/GitLab CI 集成：自动拉取失败运行并诊断
- 视觉回归辅助（需多模态模型）
- 性能测试场景生成
- 多语言 UI
- 团队协作与云同步
- 浏览器扩展：在 Jira/Confluence 页面直接生成用例

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 架构 | 纯静态站点（GitHub Pages），无后端服务器 |
| 模型 | OpenAI 兼容接口，支持 GLM / DeepSeek / OpenAI / 自定义端点；用户自配 Key |
| 密钥安全 | Key 仅存浏览器 localStorage，不上传；页面明示隐私边界 |
| 数据存储 | localStorage；支持一键导出/导入 JSON |
| 隐私 | 输入内容直接发送至用户选择的模型服务商；页面明示；不内置数据收集 |
| 性能 | 流式输出；首字节 < 3s（取决于模型服务商）；UI 交互无卡顿 |
| 可用性 | 中文 UI；响应式布局（桌面/移动）；深色模式 |
| 可靠性 | 单源失败有明确错误提示；网络重试；生成可中断 |
| 无障碍 | 语义 HTML；键盘导航；对比度达标 |

## 6. 视觉设计方向

- 工程感、信息密度适中，延续"留白"品牌的克制美学
- 深色模式为主（测试工程师偏好），纸墨色可选
- 代码块使用等宽字体 + 行号
- 模型状态、生成进度、流式光标可视化
- 不使用 emoji 图标

## 7. 验收标准（MVP）

| # | 场景 | 预期 |
|---|---|---|
| A1 | 输入登录功能需求 | ≥ 12 条用例，覆盖正常/边界/无效/权限/并发，预期结果可验证，可导出 CSV |
| A2 | 输入用例 + 选择 Playwright TS | 产出含 import/test/expect 的脚本，无固定 sleep，定位器不含绝对 XPath |
| A3 | 粘贴 CI 超时错误日志 | 输出根因分析（含日志证据行）、分类判断、修复建议 |
| A4 | 未填 API Key 点生成 | 明确提示去设置页配置，不返回虚假内容 |
| A5 | 刷新页面 | 历史会话与产出仍在 |
| A6 | 导出 → 清空 localStorage → 导入 | 数据完整恢复 |

## 8. 非目标（明确不做）

- 不执行真实测试（不启动浏览器/不发真实 HTTP 请求）
- 不替代测试管理平台（TestRail/Zephyr 等）
- 不做多用户账号体系/云同步（MVP）
- 不内置任何模型 API Key
- 不爬取盗版内容源

| 阶段 | 内容 |

| M1 · MVP | F1 用例生成 + F2 脚本生成 + F3 失败诊断 + F9 工作台基础 + 模型设置 |
